# آجِل (Ajil) — منصة إدارة ديون البقالات

منصة اشتراكات (Multi-Tenant SaaS) لإدارة البيع الآجل في البقالات: تطبيق Android يعمل بدون إنترنت، صفحة ويب للمشترك، ولوحة إدارة للمنصة. الخادم Supabase (PostgreSQL).

## التشغيل محلياً (Docker + Supabase CLI)

```bash
# 1) داخل مجلد المشروع
npx supabase init          # ينشئ supabase/config.toml ولا يمس الـ migrations
```

انسخ محتوى `supabase/config.additions.toml` إلى `supabase/config.toml` (إظهار مخطط app، hook التوكن، إعدادات الدوال).

```bash
# 2) تشغيل Supabase محلياً وتطبيق المخطط
npx supabase start
npx supabase db reset      # يطبق كل الـ migrations من الصفر

# 3) تشغيل الاختبارات على قاعدة Supabase المحلية (97 اختباراً)
for f in supabase/tests/*_test.sql; do psql "postgresql://postgres:postgres@127.0.0.1:54322/postgres" -v ON_ERROR_STOP=1 -f $f; done
```

لوحة Supabase المحلية: http://127.0.0.1:54323

> الاختبارات تُنشئ بيانات تجريبية؛ شغّل `npx supabase db reset` بعدها لتنظيف القاعدة.

## قواعد أساسية في التصميم

| القاعدة | كيف تُفرض |
| --- | --- |
| عزل كل بقالة | RLS على كل جدول بـ `store_id` من التوكن، و`branch_id` حسب صلاحية المستخدم |
| لا تعديل ولا حذف للحركات | سحب الصلاحية + Trigger يرفض أي UPDATE/DELETE |
| التصحيح بالإلغاء فقط | حركة `void` تشير للأصل، مرة واحدة، بسبب إلزامي، والمبلغ يؤخذ من الأصل |
| الموظف | يلغي حركاته فقط وخلال 24 ساعة (قابلة للتعديل في الإعدادات) |
| الأرصدة | تُحسب من الحركات، وتُخزَّن صفاً لكل (زبون، عملة)، مع دالة مطابقة يومية |
| كشف التلاعب | سلسلة بصمات SHA-256 لكل فرع + `app.verify_chain()` |
| المزامنة | `push_transactions` آمنة للتكرار، `device_gaps` تكشف الناقص، `pull_changes` بمؤشر `server_seq` |
| الجهاز | مرتبط ببقالة واحدة، جهاز الموظف يحتاج اعتماد المالك، والملغى يُرفض فوراً |
| حدود الباقة | عدد الزبائن لكل فرع، المستخدمون، الأجهزة؛ المؤرشف لا يُحسب |
| الاشتراك | بعد الانتهاء بـ 7 أيام تصبح البيانات للقراءة فقط (لا تُحذف) |
| التجربة المجانية | مرة واحدة لكل رقم ولكل جهاز |

## الدخول

رقم جوال البقالة + رقم المستخدم + كلمة المرور. في Supabase Auth يُمثَّل كل مستخدم ببريد داخلي مشتق:
`u{رقم_المستخدم}.{رقم_جوال_البقالة}@users.ajil.app` (يُبنى في التطبيق، ولا يراه المستخدم). التحقق من رقم المالك عند التسجيل يكون برمز OTP عبر Edge Function.

## الحالة والخطوات التالية

كل التفاصيل في `docs/NEXT_TASKS.md`. باختصار:
- قاعدة البيانات و Edge Functions مختبرة.
- تطبيق Flutter ولوحة الإدارة مكتوبان كاملاً **بدون مترجم** — أول خطوة `flutter analyze` وإصلاح أي خطأ.
- بوابة المزامنة `sync-push` تتحقق من توقيع الجهاز (ECDSA P-256) وتمنع الإعادة (nonce)، وفي الإنتاج تُفعَّل `require_gateway` فلا تُقبل حركة إلا عبرها.
